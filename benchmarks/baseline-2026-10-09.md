# Initial Matrix Benchmark Baseline

Date: 2026-10-09

## Environment

- CI environment: GitHub Actions, Ubuntu runner, `php:8.5-cli` container.
- Compiler: GCC 14.2.0.
- Build: standalone C11 benchmark, `-O2`, libc allocator, GNU ld wrappers around
  `malloc`, `calloc`, and `free`.
- Timing: `clock()` CPU time.
- Source: benchmark smoke run from workflow run 94, PHP 8.5 job.
- This is a **single smoke-run baseline**, not a statistically reliable comparison.
  Several operations complete in substantially less than one millisecond; those
  timing values are particularly sensitive to machine load and timer resolution.
  Repeat workloads multiple times and compare medians/dispersion before making
  algorithm or storage decisions.

Allocation counts/bytes are accumulated over each measured interval. Read workloads
allocate no memory in the measured loop. Operation workloads include temporary
buffers and result Matrix/Storage allocations for all iterations; frees are not
counted as allocation events, and requested bytes are not peak live memory.

## Interpretation limits

- Do not infer that one Storage kind or view is universally faster from this run.
- The read loops include checked-coordinate access and the cost of the selected
  Storage/view chain.
- The multiplication sample is only 32×32 and is not enough to characterize
  scaling or compare alternative algorithms.
- Use this as a reproducible first checkpoint. Future performance work should
  record machine/compiler context and use larger sizes, repeated samples, and
  medians (plus residual/correctness checks for numerical algorithms).
