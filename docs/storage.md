# Storage\n\nStorage is Numerus's internal representation layer for matrix data. It provides\none logical matrix interface while allowing the implementation to use a\nrepresentation suited to the matrix structure.\n\nStorage is **not** a PHP-facing API. Higher-level components such as Matrix\nshould depend on the opaque Storage contract rather than on its internal\nunion or allocation layout.\n\n## Core properties\n\n### Immutable\n\nA Storage instance has no mutation API.\n\nConstructor inputs are copied into memory owned by Storage. After construction,\nthe logical values and dimensions do not change.\n\nThis makes Storage suitable for structural sharing: multiple higher-level\nobjects can reference the same immutable storage without coordinating writes.\n\n### Opaque\n\nThe public header declares:\n\n```c\ntypedef struct numerus_storage numerus_storage;\n```\n\nThe structure itself is private to `numerus_storage.c`. Consumers therefore\ncannot depend on whether a matrix is dense, packed, implicit, sparse, or\nbanded.\n\n### Common logical interface\n\nEvery representation implements the same logical operation:\n\n```c\nnumerus_storage_get(storage, row, column, &value);\n```\n\nA successful read always produces a `double`, regardless of how the value is\nrepresented internally.\n\nThe checked accessor returns an explicit status:\n\n- `NUMERUS_STORAGE_SUCCESS`\n- `NUMERUS_STORAGE_INVALID_ARGUMENT`\n- `NUMERUS_STORAGE_OVERFLOW`\n- `NUMERUS_STORAGE_OUT_OF_MEMORY`\n- `NUMERUS_STORAGE_OUT_OF_BOUNDS`\n\nThe output value is not modified when a checked read fails.\n\nFor validated hot loops, `numerus_storage_get_unchecked()` skips argument and\nbounds checks. It must only be used when the caller has already established\nthat the Storage pointer and coordinates are valid.\n\n## Representations\n\n| Kind | Logical representation | Stored values |\n| --- | --- | --- |\n| Dense | Arbitrary rectangular matrix | Every element, row-major |\n| Upper triangular | Square matrix with values on/above diagonal | Packed upper triangle |\n| Lower triangular | Square matrix with values on/below diagonal | Packed lower triangle |\n| Diagonal | Square diagonal matrix | Main diagonal |\n| Identity | Identity matrix | None |\n| Constant | Every element has one value | One value |\n| Zero | All-zero matrix | None |\n| Scaled identity | Diagonal is one shared value, elsewhere zero | One value |\n| Sparse | Default value plus explicit overrides | Sorted sparse entries |\n| Symmetric | Symmetric square matrix | One triangular half |\n| Banded | Values inside fixed lower/upper bandwidth | Fixed-width row bands |\n\n### Dense\n\nDense storage is row-major and stores all `rows * columns` values.\n\n### Triangular\n\nUpper and lower triangular storage use packed arrays containing only the\nlogical triangle. Reads outside the represented triangle return `0.0`.\n\n### Diagonal\n\nOnly the main diagonal is stored. Every off-diagonal read returns `0.0`.\n\n### Identity and scaled identity\n\nIdentity stores no values: diagonal reads are `1.0` and off-diagonal reads are\n`0.0`.\n\nScaled identity stores one value. Diagonal reads return that value and\noff-diagonal reads return `0.0`.\n\n### Constant and zero\n\nConstant storage stores one value and returns it for every valid coordinate.\n\nZero storage stores no values and returns `0.0` for every valid coordinate.\n\n### Sparse\n\nSparse storage combines a default value with explicit row-major entries:\n\n```c\ntypedef struct {\n    size_t index;\n    double value;\n} numerus_storage_sparse_entry;\n```\n\nThe constructor:\n\n1. validates the matrix element count;\n2. copies the supplied entries;\n3. sorts entries by linear index;\n4. rejects duplicate indices;\n5. rejects indices outside the matrix;\n6. stores the default value.\n\nLookup uses binary search, giving `O(log k)` lookup for `k` explicit\nentries.\n\nAn empty entry set is valid and simply behaves as a constant matrix whose\nvalue is `default_value`.\n\n### Symmetric\n\nSymmetric storage keeps the lower triangle and mirrors coordinates from the\nupper triangle onto it during reads.\n\nFor a coordinate `(row, column)`, the implementation normalises it to\n`(max(row, column), min(row, column))` before accessing the packed lower\ntriangle.\n\n### Banded\n\nBanded storage keeps a fixed number of diagonals around the main diagonal.\n\n`lower_bandwidth` controls how many diagonals below the main diagonal are\nstored; `upper_bandwidth` controls how many are stored above it.\n\nCoordinates outside the configured band return `0.0`.\n\nBandwidths larger than the matrix dimensions are clamped to the largest\nmeaningful values. For an empty matrix, both bandwidths are normalised to zero.\n\nThe internal layout uses a fixed row width:\n\n```text\nlower_bandwidth + 1 + upper_bandwidth\n```\n\nThis keeps coordinate access predictable and avoids storing structural zeros\noutside the configured band.\n\n## Memory management\n\nThe extension build uses PHP’s Zend Memory Manager:\n\n- `emalloc()`\n- `ecalloc()`\n- `efree()`\n\nThis keeps Storage allocations within the extension’s normal PHP memory\nmanagement model.\n\nThe standalone native C tests compile with\n`NUMERUS_STORAGE_USE_LIBC_ALLOC` so that `numerus_storage.c` can be tested\nwithout embedding the PHP runtime. That switch is a test/build convenience;\nthe extension itself uses Zend Memory Manager.\n\n## Error and ownership rules\n\nStorage owns every dynamically allocated buffer created by its constructors.\n\nInput arrays are never retained by reference. The caller may therefore release\nor reuse its input buffers after a successful constructor call.\n\nOn constructor failure, no partially constructed Storage is returned: the output\npointer is reset to `NULL` after cleanup.\n\nThe checked getter distinguishes failure from a legitimate numeric zero. In\nparticular, `0.0` is always a valid matrix value and is never used as an error\nsentinel.\n\n## API\n\nThe public API is declared in [`numerus_storage.h`](../numerus_storage.h).\n\nMain operations:\n\n- `numerus_storage_create_*()` — construct an immutable representation.\n- `numerus_storage_get()` — validated element access.\n- `numerus_storage_get_unchecked()` — unchecked hot-path element access.\n- `numerus_storage_destroy()` — release Storage and owned memory.\n- `numerus_storage_rows()` / `numerus_storage_columns()` — dimensions.\n- `numerus_storage_kind_of()` — representation kind.\n\nThe header contains the authoritative function-level contracts.\n\n## Testing\n\nThe native test suite exercises:\n\n- value access for every current representation;\n- implicit zero regions;\n- sparse sorting and lookup;\n- symmetric mirroring;\n- band boundaries;\n- dimensions;\n- checked bounds handling;\n- NULL argument handling;\n- preservation of the output value after failed reads;\n- the unchecked accessor.\n\nThe native suite is compiled with strict warnings:\n\n```sh\ncc -std=c11 -Wall -Wextra -Wpedantic -Werror \\n  -DNUMERUS_STORAGE_USE_LIBC_ALLOC \\n  -o tests/storage_test tests/storage_test.c numerus_storage.c\n./tests/storage_test\n```\n\n## Scope boundary\n\nStorage is deliberately limited to representation and element access.\n\nIt does not currently implement:\n\n- matrix arithmetic;\n- decomposition algorithms;\n- BLAS/LAPACK integration;\n- iteration APIs;\n- expression trees;\n- PHP object wrappers;\n- mutation;\n- high-level statistical or optimisation APIs.\n\nThose concerns belong to higher layers and should be introduced only when\nthere is a concrete numerical requirement for them.\n
